Architecture and next steps

  
Architecture. One orchestrator (run()) owns state: a history array of score, delta, critique and draft per round, plus a rolling memory string. Each agent is a single system prompt plus a live Messages API call with retries and backoff. The loop is a while(true) that evaluates, runs the stop check in order (plateau, threshold, cap), and only then critiques, improves and remembers.

  
Extension ideas.
  • Add a brand-voice corpus to the Evaluator and a second, independent judge to reduce scoring bias.
  • Run two Executors in parallel and let the Evaluator pick the stronger starting draft.
  • Pipe the final copy to a CMS or A/B test tool, then feed conversion data back into memory.

  
Prompts to go further.
  • “Add a human-approval gate between rounds and persist runs to IndexedDB.”
  • “Add a Router agent that picks the agent set from the brief.”
  • “Compare plateau deltas of 0.5, 1.5 and 3 across 10 briefs and chart cost versus score.”
