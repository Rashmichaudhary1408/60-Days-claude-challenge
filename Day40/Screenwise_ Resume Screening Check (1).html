How this was built

The system prompt

The prompt gives Claude one narrow job (screening a resume against one posting), forbids invented facts, and demands strict JSON so the interface can draw a dial, bars, tags and highlights instead of dumping prose. Scoring is anchored to weighted categories so the same resume gets stable scores. Edge cases are handled in the prompt itself: non-resume input, missing job description, and attempts to override instructions each return a short, structured refusal with valid: false.



Why the interface fits


    

  • The score dial and category bars answer “how am I doing” in one second; detail comes after.
    • 

  • Highlighting the resume in place ties every critique to the exact line, so users fix rather than reread a report.
    • 

  • Missing keywords are clickable tags that explain why each term matters to the posting.
    • 

  • Priorities are ordered so the first fix has the biggest effect.
    • 

  • Loading, empty and error states each say what is happening and what to do next.
    • 



How to extend it


    

  • Memory: store each scored version in the page’s database capability and chart score change across edits.
    • 

  • Tools: give the model a function that counts keyword frequency or checks date gaps, so those facts are computed, not guessed.
    • 

  • Multi-step flow: add a second call that rewrites the weakest section after the user approves the suggestions.
    • 

  • File upload: read a PDF or DOCX in the browser and fill the resume box automatically.
    • 

  • Outside Claude: the page asks Claude through the viewer’s runtime. To host it elsewhere, replace the ask() function with a fetch to the Messages API and add your own API key on a server.
